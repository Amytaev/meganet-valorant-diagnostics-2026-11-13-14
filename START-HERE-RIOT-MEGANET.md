# Valorant × Meganet — техническое сопровождение для Riot и ISP

**Срез исследования: 15 ноября 2026.** Местоположение пользователя: Алматы, Казахстан, доступ Meganet (NLS Kazakhstan), Windows 11, Wi-Fi 5 ГГц. Пользователь выбирал Stockholm в подтверждённых игровых сессиях; география каждого исторического подключения независимо не проверена.

> **Ключевой вывод:** Повышенный игровой RTT подтверждён штатными журналами Valorant, включая 328,12–383,31 мс 14 ноября. Есть как совпадения с контрольными сетевыми аномалиями, так и игровые пики при нормальном ICMP до пяти контрольных адресов. Единственная первопричина, конкретный виновный оператор или физический сервер **не установлены**. Не следует считать `ping` до Riot IP прямым измерением игрового UDP-потока.

## Приоритетные интервалы для корреляции

Все времена ниже даны в **UTC+05:00 (Алматы)** и **UTC**; записи пороговые, не непрерывный временной ряд.

| Алматы, UTC+05 | UTC | Наблюдение и app endpoint |
|---|---|---|
| 14.11 00:07:16 | 13.11 19:07:16 | Valorant ≈198–202 мс при пяти спокойных контрольных направлениях; `185.40.64.1:7039` |
| 14.11 00:58:09–00:58:15 | 13.11 19:58:09–19:58:15 | Игровые **162,91 → 206,84 → 172,31 → 226,09 мс**; RETN-контроли временно около 150–180, ближние контроли также слегка менялись; `185.40.64.1:7354` |
| 14.11 14:27:45–14:29:59 | 14.11 09:27:45–09:29:59 | Восемь игровых пороговых значений **328,12–383,31 мс**, 26 input replication stops и очередей overflow; **335/335** успешных ICMP по пяти контрольным целям; `185.40.64.1:7004` |
| 14.11 около 14:31:45 | 14.11 около 09:31:45 | После перезапуска подтверждены полученные игровые пакеты от `162.249.72.1:7004`, пользователь сообщил RTT ≈100–110 мс; причинность смены адреса не установлена |
| 15.11 01:08:44 | 14.11 20:08:44 | Игровые **155,46 мс** при шлюзе 1–2, near 2–4, CF 25–27 и RETN 91–93 мс; `185.40.64.1:7216` |

**Важно:** `185.40.64.1` и `162.249.72.1` — адреса, связанные с игровым соединением в логах приложения. Это не доказанные физические IP серверов Stockholm. Присутствуют как совпадения контролей с игровыми пиками, так и контрпримеры. Игровые журналы автоматически фиксируют только пороговые Average Ping `>=120` мс — полноценный числовой ряд 90–119,99 мс отсутствует. Записи не равны независимым инцидентам или длительности повышенного RTT.

## Что требуется от сторон

**Riot / Riot Direct:** по исходным match IDs, переданным приватно владельцем, проверить server-side и ingress-поток, forward/reverse packet/ACK timing, потери/reorder, server tick, значение пороговых предупреждений и доступность штатного экспорта непрерывного Network RTT, jitter, loss in/out, RTT+Processing Delay. При возможности указать диагностический публичный адрес/методику для ISP; не требовать публикации приватного backend IP.

**Meganet / операторы:** используя конфиденциально предоставленные абонентские WAN/NAT сведения, проверить egress/peering/BNG/CGNAT/ECMP, forward/reverse route, queue/drop/reorder и QoS на соответствующих временах и игровых направлениях. Одних destination IP:port недостаточно для однозначной идентификации UDP 5-tuple или обратного пути; исходный UDP-порт достоверно не известен. Трассировки к Riot с отсутствующими ICMP Echo Reply не означают 100% UDP packet loss.

**Владелец:** оригинальные RRT ZIP и точные match/account identifiers передаются только в приватную поддержку Riot. Не публиковать секреты, токены, полные Riot Logs, WAN-адрес абонента и данные договора. Этот репозиторий содержит публичные **обезличенные производные материалы**, не сырые журналы.

Детали методики обезличивания: [PUBLICATION-NOTES.md](PUBLICATION-NOTES.md). Публикация не означает, что обращение в Riot или Meganet было автоматически отправлено.
