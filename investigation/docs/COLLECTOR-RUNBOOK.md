# Непрерывный мониторинг Windows — схема 3

Основной процесс работает до явного STOP. Стандартного лимита 600 секунд больше нет. Ротация, промежуточный анализ и завершение ответа Codex не останавливают сбор. Для проверок можно явно задать DurationSeconds; значение по умолчанию 0 означает непрерывно.

## Запуск

Из папки valorant-network-investigation, обычный PowerShell:

```powershell
.\scripts\Start-QuietSession.ps1
```

Нужен установленный Python 3.12+ с pythonw.exe; сторонних пакетов нет. На игровом ПК проверен Python 3.14. Launcher использует штатный Win32_Process.Create через WMI, ShowWindow=0, ordinary user и проверяет WmiPrvSE.exe как родителя. Не создаются служба, задача планировщика или автозагрузка. Windows может поместить процесс в служебный job; сам флаг process_in_job не доказывает принадлежность к Codex. Подтверждается независимый создатель, обычный токен и продолжение работы после завершения запускающего клиента.

Проверка готовности требует результатов ICMP без ProbeError от каждой цели, heartbeat и совпадения PID. Одного PID или созданной папки недостаточно. При неуспешной проверке своему новому процессу запрашивается STOP. Ядро также держит именованный mutex на пользовательский сеанс; повторный штатный запуск возвращает текущий монитор.

По умолчанию raw/continuous/active.json указывает на текущий каталог. В нём metadata.json, status.json, commands/ и telemetry-00000001.jsonl, telemetry-00000002.jsonl и т. д. Каталог raw игнорируется Git. При длинном пути Windows лучше выбрать более короткий OutputRoot; проверка запуска обязательна.

```powershell
python .\scripts\continuous_monitor.py status --root .\raw\continuous
```

Status показывает возраст heartbeat, PID, пригодные цели, статусы проб, очередь диска и давление на хранение. Heartbeat старше 10 секунд означает stale_or_interrupted, а не доказательство работающего процесса. Отсутствие DONE после прерывания не выдаётся за штатное завершение.

## Метки без переключения окон

Сочетания регистрируются через RegisterHotKey в невидимом окне с NOACTIVATE, без хуков клавиатуры, записи обычных клавиш, нажатий от Codex или оверлея:

| Сочетание | Действие |
|---|---|
| Ctrl+Alt+Shift+F8 | отметить скачок |
| Ctrl+Alt+Shift+F9 | отметить восстановление |
| Ctrl+Alt+Shift+F10 | произвольная метка |
| Ctrl+Alt+Shift+F11 | явно остановить монитор |

В status.json доступны только успешно зарегистрированные сочетания. Занятое сочетание не переназначается у другого приложения. Запись содержит время обработки события с миллисекундами; это не автоматическое измерение RTT. Переключения активного окна не происходит. Сеанс, window station и desktop сохраняются в metadata для проверки доступности меток во время игры.

Codex может отметить событие по сообщению пользователя через очередь команд. Можно также внести числа вручную:

```powershell
.\scripts\Add-GameMarker.ps1 -Event spike -RttAverageMs 180 -RttMaxMs 190
.\scripts\Add-GameMarker.ps1 -Event recovery -RttAverageMs 95
```

Это условные примеры. Не выдавать время внесения ретроспективного сообщения за секунду самого пика. Для известного времени использовать ObservedAt с UTC-смещением. Команды пишутся атомарным переименованием и забираются основным процессом; они не перезапускают его.

## Нагрузка и источники

Пять целей: 192.168.123.1, 89.38.164.205, 1.1.1.1, 87.245.238.34 и 87.245.233.166. Это шлюз, near-hop, публичная цель и два отвечавших RETN узла из предыдущего этапа. ICMPv4: 32 байта, каждые 2 секунды на цель, timeout 1500 мс. До пяти потоков одного основного процесса ожидают Windows IcmpSendEcho2. После задержки или пробуждения не отправляется догоняющий шквал; фактические интервалы и пропуски фиксируются.

Раз в 30 секунд отдельный низкоприоритетный helper PowerShell читает счётчики адаптеров, netsh wlan show interfaces, наличие игры и её локальные UDP-привязки. Начальный/редкий снимок включает маршруты, драйверы и выбранные пути. Helper ограничен 8 секундами и не блокирует основной цикл; при зависании завершается только собственный helper. В обычном режиме есть один основной монитор и кратковременный вспомогательный процесс, а не цепочка диагностических сессий.

Полные игровые журналы, файлы авторизации и память не читаются этим ядром. Поддерживаемый источник непрерывных клиентских Network RTT / loss не подтверждён; прямое автоматическое получение этих показателей отключено. Публичная документация Riot описывает другие API, а в игре доступны графики RTT/loss. До появления проверенного источника используются ручные значения/метки. TCP или локальные UDP-порты не подменяют игровой RTT. Захват UDP, ETW/pcap, инъекции и обход Vanguard не используются.

## Аномалии

config/anomaly-baseline-2026-11-14.json содержит замороженные пороги из отобранных исторических ICMP CSV (299 успешных проб исходных целей и 149 нового RETN hop). Порог в мс: max(median + max(10, 6*MAD), p95 + 10). Для рабочего набора: шлюз 15, near-hop 16, Cloudflare 38, RETN-1 109, RETN Stockholm-labeled 106. Исходные файлы и размеры выборок сохранены в конфигурации.

Выход за порог, три квалифицированных последовательных ICMP-неответа и проблемы качества записываются отдельно. Аномалия ICMP не доказывает лаг игры или вину узла. ProbeError и подозрительно ранний TimedOut не трактуются как обычные сетевые потери. Для неизвестной цели порог формируется после 60 успешных ответов и явно помечается как начальная живая калибровка, которая сама могла проходить при плохой сети. Пороги не подстраиваются непрерывно под скачок.

## Файлы и диск

Единый JSONL содержит schema, run_id, глобальный sequence, UTC/local с миллисекундами, монотонное время и тип записи. Ротация по 15 минутам либо 4 МиБ выполняется внутри того же процесса. Старый файл закрывается, новый открывается, номера проб продолжаются. Каждая строка сразу передаётся ОС; fsync каждые 5 секунд, также при закрытии сегмента. Миллисекундный формат не гарантирует абсолютную точность часов или регистрацию всех коротких сетевых событий.

Согласованный пользователем мягкий бюджет — 512 МиБ. Удаляются только старые закрытые непомеченные сегменты данного run. Два последних сегмента всегда сохраняются; аномалия/ручная метка закрепляет текущий и предыдущий сегмент плюс последующие 120 секунд. Закреплённые инциденты автоматически не удаляются и могут превысить бюджет. segments.json сохраняет сведения об удалённых обычных диапазонах sequence. Это кольцевая обычная история с защищёнными инцидентами, а не обещание бесконечного хранения каждой пробы.

storage_pressure выставляется при превышении мягкого бюджета либо свободном месте менее 1 ГиБ. Нужен архив/экспорт владельцем; тихий режим не показывает диалоги. При ошибке записи измерения продолжаются с буфером до 10 000 записей в памяти и повторной попыткой. При переполнении буфера dropped_memory_records явно считает утрату. Физически заполненный/неисправный диск и потеря питания исключают гарантию сохранения всех данных; не заявлять её. Артефакты измерительных ошибок не считать доказательством сетевых потерь.

## Промежуточный анализ

```powershell
python .\scripts\analyze_continuous.py .\raw\continuous
```

Анализатор фиксирует committed sequence из heartbeat, читает только полные строки до начального размера файлов и этого watermark. Последующие пробы продолжаются и попадут в следующий анализ. Память ограничена гистограммами RTT и последними 1000 событиями, а не всей историей строк. Получаются точные min/avg/max/p95 успешных ICMP, количества статусов, временные окна, интервалы проб, события и пропуски/удаления. analysis.latest.json — промежуточный результат, complete=false, пока нет DONE.

Ротация или удаление старого обычного файла во время чтения учитывается как недостающий диапазон; отсутствующие строки не превращаются в нулевые потери. Старый analyze_session.py остаётся для исторических CSV схемы 2.

## Остановка и итог

```powershell
.\scripts\Stop-QuietSession.ps1
```

Команда атомарно запрашивает STOP и ждёт до 10 секунд подтверждения. Ядро завершает текущие ICMP, закрывает журнал, сохраняет metadata/status/DONE и освобождает горячие клавиши. Wrapper затем анализирует всю оставшуюся историю в analysis.latest.json и FINAL-RESULTS.md. После F11 или записи STOP анализ можно выполнить отдельно тем же wrapper: остановленный монитор не запускается заново.

При штатном выключении/выходе пользователя невидимое окно получает WM_ENDSESSION, просит основной цикл закончить и даёт ему до двух секунд. Выключение не блокируется и не отменяется. Сбой питания или принудительный kill может оставить последний хвост и отсутствие DONE; анализ игнорирует неполную строку и сообщает незавершённость. Перезагрузка не устанавливает автозапуск — возобновить монитор нужно явно.

В конце расследования Codex выполняет STOP, проверяет DONE и очередь записи, анализирует сохранённые данные, обновляет технический отчёт и только после проверки секретов коммитит отобранные материалы в приватную ветку. Завершение текущего ответа не означает конец расследования и не вызывает STOP.

## Проверки и первичные источники

```powershell
python -m unittest discover -s .\tests -v
.\tests\Test-CollectorLifecycle.ps1
```

Windows lifecycle использует только 127.0.0.1, отдельный тестовый корень, проверку WMI-родителя, ротации и анализа, реального Echo-ответа, STOP и сообщения собственному скрытому окну. Изолированный тестовый mutex разрешён только для loopback без зарегистрированных горячих клавиш; рабочий монитор ради тестов не останавливается. Для реальных адресов всегда действует общий singleton. Тест WM_ENDSESSION не посылает команду выключения Windows и не трогает чужие окна.
