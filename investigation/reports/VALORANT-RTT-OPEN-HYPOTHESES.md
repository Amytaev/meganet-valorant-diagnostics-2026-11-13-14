# Проверяемые гипотезы и различающие проверки

Это план получения недостающих доказательств, а не разрешение запускать проверки. Никакие новые игры, активные сетевые измерения, настройки, packet capture или обращения в этом этапе не выполнялись. Полные наблюдения и контрпримеры — в [основном отчёте](VALORANT-RTT-OPEN-INVESTIGATION.md).

| H9: часы/API создают мнимое расхождение | Известные старые ошибки исключены; wall−monotonic дневного run ±1 мс, native RTT правильный prefix, непрерывные seq | Офлайн replay/clock audit выполнен; Riot уточняет временную базу логов и метрики | Минутной ошибки, объясняющей эпизод, не найдено; для субсекундной причинной последовательности нужна лучшая синхронизация | Универсальная версия ослаблена; остаточные timing limits сохранены |
| H10: субъективное ISP сравнение смешивает backend/время/Wi-Fi | Нет контролируемой Beeline серии; Meganet тоже даёт 85–93 | Пользователь и провайдеры: чередующиеся сопоставимые access/region/time/endpoint наблюдения, желательно одинаковый backend через Riot | Если разница исчезнет при выравнивании доступа/контекста, конкретная версия «именно ISP» ослабнет; одинаковый IP не гарантирует один backend | Эффект смены ISP количественно не установлен |

Для каждого нового эпизода необходимы непрерывные **Network RTT avg/max, RTT jitter, RTT+Processing Delay, inbound/outbound loss и frame time** с часами, endpoint mapping и те же ICMP-контроли. Именно отсутствие нормальных 90–119,99 делает невозможным определение истинных переходов, доли времени и длительности. Если Riot не поддерживает экспорт, допустим следующий отдельно обсуждаемый вариант: штатные графики, которые записывает сам пользователь, с последующим согласованным OCR. Общий UDP capture, память процесса и Vanguard bypass не являются частью плана.

Предоставление абонентского WAN/NAT, договора и реальных match/account identifiers — только самим владельцем в приватном канале поддержки. Публичная таблица намеренно содержит только технические назначения и обезличенные привязки.
