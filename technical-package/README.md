## Самое важное ограничение

Игровой RTT 300–400 мс сообщён игроком; контроли 2/3/24/93/92 мс — медианы по 24 автоматическим ICMP-пробам в близком окне 14:29:10.353–14:29:58.079. Не выдавать это за посекундно синхронизированный игровой ряд. Нулевые ICMP неответы и звёздочки tracert не измеряют игровой UDP loss и не локализуют виновный узел. Смена адреса после перезахода совпала с восстановлением, но клиентское состояние тоже изменилось.

## Как читать числа

Основные серии: ICMPv4 32 байта, 2 с, timeout 1500 мс; H01 — ранняя 800-мс серия только контроля качества. 13205 основных попыток = 12870 пригодных Success + 335 H01. JSONL и CSV одной непрерывной серии содержат одни и те же пробы: не суммировать. `rtt_ms` берётся только из Success; ожидание API не равно RTT. p95 — ближайший ранг. Подробные правила — [методика](01_reports/METHODOLOGY.html).

Исторические pings.csv и TTL JSONL сохранены побайтно. Непрерывные журналы экспортированы только с probe-полями; исходные числовые значения/времена/статусы не исправлены, оригинальные seq оставлены. Пробелы seq в экспорте означают удалённые не-пробные записи. metadata обезличены. Все исходные непрерывные sequence проверены до фильтрации.

## Приватность и целостность

В архиве нет паролей, токенов, полных Riot-журналов, имён игроков, SSID, MAC/BSSID, GUID, IP самого ПК, имени пользователя, персональных абсолютных путей, идентификатора абонента или заявки. Адреса целей/маршрутизаторов и шлюза оставлены как измерительные назначения. Системные снимки и полный репозиторий не включены. Абонентские данные владелец сообщает оператору отдельно.

После распаковки можно проверить SHA256SUMS.txt: формат каждой строки `SHA256  относительный/путь`. В PowerShell `Get-FileHash -Algorithm SHA256 -LiteralPath <файл>`; сравнивать хеш с соответствующей строкой. Реестр и аудит — в 08_integrity. SHA-256 проверяет неизменность, а не точность часов или причину проблемы.
